Lifecycle & transitions

Lifecycles you can defend to a regulator.

Every entity has a lifecycle. Every transition is a contract — preconditions, Actors bound to roles, dual control where you need it, wait conditions that hold until they are met, events fired to downstream systems on success. Configure transitions in the model, not in code.

Whether it's an approval, an onboarding, a case escalation, or a status change on a piece of equipment — the same governance rigour applies, and the platform records who decided what, when, and why. Compensating transactions on rollback. No silent deletes.

Location

Every record knows where it is.

Switch on Location for an entity and each record carries one place — a point, a line or an area. It is set when the record is created, shown beside the fields you are reading, and opens onto a map when you need the context. A request at a property takes the property’s place: entered once, never re-keyed.

Lists and Work gain a Map layout with the same filters, each record marked in its stage colour, and every move is on the record’s history. Not a mapping tool. The work happens somewhere, and the record says where.

Auditability

Every action recorded. Nothing destroyed.

Every action a user or AI Agent takes generates an immutable, tamper-proof event in the audit store — with dual attribution when an Agent participated, cryptographic sealing at terminal stages, and field-level GDPR classification at extraction.

Rollback never deletes. It records a compensating transaction that undoes the original action while preserving the original record. The checksum chain holds. When a regulator asks “who decided this, and why?”, the platform answers without you having to assemble it from logs.
